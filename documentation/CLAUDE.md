# Vaulted Money — AI Agent Rules

Project rules for AI agents working on this codebase. Read this before making any change.

---

## Repository hygiene

**Only source belongs in git.** Never commit anything that can be reproduced by running a command. If you create or encounter a generated artifact, add it to `.gitignore` instead.

Generated outputs that must stay out of git:

| Path | Regenerated by |
|---|---|
| `dist/`, `dist-ssr/` | `pnpm build` |
| `dist-electron/` | `pnpm electron:compile` |
| `release/` | `pnpm electron:build` |
| `coverage/` | `pnpm test:coverage` |
| `node_modules/`, `.cache/` | `pnpm install` |
| `android/app/src/main/assets/public/` | `cap sync android` |
| `ios/App/App/public/` | `cap sync ios` |
| `android/capacitor-cordova-android-plugins/` | `cap sync` |
| `ios/capacitor-cordova-ios-plugins/` | `cap sync` |

Before committing, ask: *"Can this be reproduced by running a command?"* If yes, gitignore it.

## Architecture principles

- **Privacy-first**: No data leaves the device unless explicitly exported by the user. API keys are stored locally and never included in exports.
- **Local-first**: The app must work 100% offline. IndexedDB via Dexie is the primary data store.
- **Routes live in `src/App.tsx`**: Do not scatter route definitions elsewhere.
- **Pages in `src/pages/`**, components in `src/components/`, hooks in `src/hooks/`.
- For mobile-specific work, consult `documentation/IOS_RULES.md` and `documentation/ANDROID_RULES.md`.

## Coding rules

- TypeScript: `camelCase` for variables/functions, `PascalCase` for components and classes.
- Use descriptive names — avoid abbreviations that require context to decode.
- Comment non-obvious logic; add multi-line comments for core business logic.
- Never commit secrets, API keys, or `.env` files.
- Never push code that does not build or pass type-checking.

## Static assets in Electron

Never reference public assets with absolute paths (`src="/logo.png"`). Under Electron's `file://` protocol, `/` resolves to the filesystem root, not `dist/`.

**Always use Vite static imports instead:**

```tsx
// ✅ correct — Vite hashes and bundles the path
import logoSquareDark from "@/assets/logo-square-dark.png";

// ❌ broken in Electron builds
<img src="/logo-square-dark.png" />
```

## Performance — lessons learned

These patterns were discovered fixing real bottlenecks in this codebase.

**Tiered useMemo for global derivations**
Global state (e.g. running balances) must derive from the global data source only — never from a filtered view. Compute the global cache in one `useMemo`, then project it onto the filtered view in a separate, cheaper step. Coupling both to the filtered list causes full recalculation on every filter change.

**Stabilise handlers passed to memoised lists**
`React.memo` on a list row is useless if the parent passes new inline arrow functions as props on every render. Wrap all handlers passed to large lists or memoised components in `useCallback`.

**Fast-forward fixed-interval recurring transactions**
Do not iterate from a transaction's start date to project into a future window. For daily and weekly intervals, use arithmetic (`differenceInDays`, `differenceInWeeks`) to jump directly to the first occurrence in the window — O(1) instead of O(N). Leave monthly/yearly as iterative to handle variable-length months correctly.

**Hoist property accessors outside sort comparators**
Parsing nested key paths (e.g. `"category.name"`) inside a sort comparison runs O(N log N) string splits. Compute the accessor strategy — simple key or path getter — once before the sort, then reuse it inside the comparator.

## Accessibility — lessons learned

**Interactive table cells must be `<button>` elements**
`div[onClick]` breaks keyboard navigation and screen readers. Reset button styles with `bg-transparent border-0 p-0 text-left` to preserve visual appearance. Add `aria-label` for context.

**Sortable column headers**
Keep `aria-sort` on the `<th>` element; move the click handler to a child `<button type="button">` that fills the cell. Use flex utilities (`justify-end`) for alignment. Mixing both on `<th>` breaks semantic structure.

**TooltipProvider is already mounted in Layout**
`Layout.tsx` wraps the authenticated app in a `TooltipProvider`. Do not add a local one — use `Tooltip`, `TooltipTrigger`, and `TooltipContent` directly inside any authenticated route.

**Combobox (cmdk) interaction**
`Combobox` fields render as `<input>` elements, not `button[role='combobox']`. Target them by placeholder text (e.g. `"Search accounts..."`). Select results via `role="option"` or `[cmdk-item]`.

## Security — lessons learned

These vulnerabilities were found and fixed in the Electron IPC layer.

**IPC filename validation**
`path.join('/safe/dir', '/etc/passwd')` returns `/etc/passwd` — Node discards previous segments on absolute paths. Always call `path.basename()` on renderer-supplied filenames and reject any value containing `/`, `\`, or `..`.

**File extension allowlist**
Sanitising the filename is not enough. Restrict writable extensions to an explicit allowlist (`.json`, `.lock`). Unrestricted extensions allow writing `.sh` or `.bat` startup scripts even with path-traversal protection in place.

**Folder authorisation allowlist**
Never trust a directory path received from the renderer. Maintain an allowlist of authorised directories in the Main process. Expand the allowlist only when the user explicitly selects a folder via `dialog.showOpenDialog`. Validate every write request against the list before writing.

**CSP must be build-time only**
Injecting a `<meta http-equiv="Content-Security-Policy">` tag into `index.html` directly breaks Vite's dev server (HMR uses inline scripts). Use a Vite plugin transform with `apply: 'build'` so the CSP header is only added to production output.

**CSV export sanitisation**
Sanitise formula-injection prefixes (`=`, `+`, `-`, `@`) before writing CSV output. But preserve valid numeric strings: `-100` is data, not a formula. Check the regex against a numeric format before escaping to avoid corrupting legitimate negative values.

## Dependency updates — lessons learned

Dependabot opens one grouped PR against `pre-prod` every week. These patterns came from fixing those PRs when CI went red.

**Reproduce every CI step before pushing a fix**
CircleCI runs lint, typecheck, format check, `pnpm test:coverage`, `pnpm build` and `pnpm audit --prod --audit-level=moderate`. `pnpm validate` covers only the first three, so run the rest too (see Quality checks). A new security advisory can fail the audit even when no code changed. Fix it with a patched version in `pnpm.overrides`.

**Bisect the grouped update, then fix the cause**
When a grouped bump breaks something, check out `pre-prod`, bump the suspect packages one at a time (`pnpm add -D <pkg>@<version>`), and rerun the failing check to find the culprit. Fix the root cause rather than pinning the old version. Pin only when upstream is incompatible, and then add a Dependabot `ignore` entry with a tracking link, as `.github/dependabot.yml` does for TypeScript.

**Tests must not depend on focus left behind by earlier tests**
Since jsdom 30.1, removing a focused element (which Testing Library's cleanup does) hands focus to the Document, and the next `focus()` fires a `blur` on `window`. Radix menus and selects close on window blur, so a dropdown test that ran after another focus-moving test never saw its menu open. `src/tests/setup.ts` resets focus before every test; keep that reset when editing the setup file. `src/tests/test-environment-focus.test.tsx` guards it.

**Commit the regenerated acknowledgments**
`pnpm build` and the test suite regenerate `src/data/acknowledgments.generated.ts` from installed versions. Commit the regenerated file along with the dependency bump so the Acknowledgments page lists the versions that actually ship.

## Quality checks

```bash
pnpm lint           # ESLint
pnpm format:check   # Prettier
tsc --noEmit        # TypeScript
pnpm test:coverage  # Vitest + coverage
pnpm build          # Production build
pnpm validate       # Combined lint + typecheck
pnpm audit --prod --audit-level=moderate  # Security audit (CI blocks on this)
```
