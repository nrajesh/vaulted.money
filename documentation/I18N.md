# Translations

The app ships English, Spanish, Chinese, Dutch and Tamil. Most of the text was written in English first and translated by machine, so a native speaker should review it before it is relied on. Text in `src/i18n/areas/` says so in its header comment.

## Where text lives

- `src/i18n/resources.ts`: the original bundles (layout, dialogs, transactions header, settings).
- `src/i18n/homeTranslations.ts`: the marketing home page.
- `src/i18n/areas/`: everything added since, **one module per area of the app with all five languages side by side**, so a reviewer can compare them. They are merged into the bundles at load; a key that already exists in `resources.ts` always wins.

Current areas: `gaps` (keys English had but other languages lacked), `shell` (keys code used without defining), `ledgerEntry`, `management` (Accounts, Vendors, Categories), `budgets`, `transactionsTable`, `feedback`, plus the dashboard and dialog keys that were added to `resources.ts`.

## Adding text to a screen

1. Write `t("area.key", { defaultValue: "English text" })` in the component. Use `{{placeholders}}` for numbers and names, never string concatenation: word order differs between languages.
2. Add the key to a module in `src/i18n/areas/` (or a new one, registered in `areas/index.ts`) for **all five languages**.
3. Plurals: define `key_one` and `key_other` and pass `count`. Chinese only needs `_other`.
4. Dates: use `formatDisplayDate(date, i18n.language)` (`src/utils/dateFormat.ts`), not date-fns `format`, which always prints English month names.
5. Do not translate data the user typed, or stored values such as account types (`Checking`); map those to a label at display time.

## What the tests enforce

- `src/i18n/dashboardTranslations.test.ts`: every language has every key English has, and keeps the same `{{placeholders}}`.
- `src/i18n/coverageGuard.test.ts`:
  - every `t("key")` in the code is defined in the English bundle (a key with only a `defaultValue` shows English in every language);
  - hard-coded English in UI files may not grow beyond `hardcodedTextBaseline.json`, so new screens must use translations. After translating a screen, lower its allowance with `UPDATE_I18N_BASELINE=1 pnpm vitest run src/i18n/coverageGuard.test.ts`.

## Not translated yet

The baseline file lists every remaining file and how many strings it still hard-codes. The largest are the Settings, Data Management, Scheduled transactions, Backup, CSV import, Add/Edit budget and AI provider dialogs.
